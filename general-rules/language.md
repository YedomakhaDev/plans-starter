# Language

Clients are English-speaking. The rule is simple: everything that goes outside or lives in code is in English. Everything that's only for you and the agent can be in your working language.

## English only

- Code: variable, function, class, and file names.
- Code comments, docblocks, READMEs inside the project code.
- Commits, branches, pull requests, code review.
- Everything the client or agency sees: emails, estimates, reports, questions, website copy.
- File and folder names in `_plans/`.

## Working language is fine

- Talking to the agent.
- Your notes, decisions, tasks, backlog, open questions (if they don't go to the client).
- The project's `AGENTS.md` — the agent understands any language but writes code and commits in English.

## Mixed

- **Client correspondence and briefs** — keep the original, in English. Your summary at the end of the file can be in your working language.
- **Estimate:** the client version is in English. Internal assumptions and risks can be in your working language, in a separate section.
- **Questions for the client:** write them in English right away, even if they're recorded in a non-English `open-questions.md`.

## For the agent

If a document is meant for the client or agency — write it in English, American spelling (color, optimize), even if the request is in another language. If it's unclear who the document is for — ask.
